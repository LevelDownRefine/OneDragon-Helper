# 启动性能实验

基线：`1767da4`；实验分支：`codex/startup-performance`。

## 改动

- CLI 分流后才导入 Qt、QML 桥接和拖放模块。
- 更新网络库 `requests` 在检查或下载更新时导入；本地版本信息仍可直接读取。
- 配置、每日计划、运行确认、更新弹窗在打开时导入。
- 启动日志增加 GUI 导入、QApplication、QmlBridge 和首帧提交阶段；QML 加载完成不再标成窗口已显示。

代价是相关模块的导入时间转移到第一次使用；更新网络操作仍在原有工作线程执行。后续使用复用 Python 模块缓存。未更换打包器或引入新依赖。

## 测量

Windows，Python 3.12.10，PySide6 6.8.0.2，同一虚拟环境。基线和修改版交替运行 7 轮，均为新进程，禁止写入 `.pyc`，取中位数。文件系统缓存已预热，不代表重启电脑后的冷启动。

| 指标 | 基线 | 修改后 | 降幅 |
| --- | ---: | ---: | ---: |
| 入口导入进程总耗时 | 519.5 ms | 223.3 ms | 57.0% |
| 入口与 GUI 模块导入进程总耗时 | 512.7 ms | 350.7 ms | 31.6% |
| 源码入口到首帧提交 | 656.8 ms | 520.5 ms | 20.8% |

前两项分别运行 `python -c "import src.launcher"` 和 `python -c "import src.launcher; import src.gui.main_window"`，包含进程创建、解释器启动和退出。基线入口已提前导入 GUI，因此这两个基线值接近。

首帧实验从应用模块导入前计时，在 `QQmlApplicationEngine.objectCreated` 时连接窗口的 `frameSwapped`，第一次触发即记录并退出。使用 `QT_QPA_PLATFORM=offscreen`、临时配置和资源副本、空脚本列表、`--after-update`；不运行外部脚本，不读取个人配置，不删除用户全局 QML 缓存。首帧时间不包含解释器启动与夹具准备。

首帧原始样本（ms）：

- 基线：748.7、648.9、665.2、652.8、676.7、652.8、656.8。
- 修改后：561.7、506.2、506.8、520.5、525.7、537.4、516.8。
- 修改后启用隔离的 QML 缓存：603.3、513.4、525.3、516.2、506.0、501.5、496.5。

QML 缓存中位数为 513.4 ms，比不启用仅少 7.1 ms。考虑此前的缓存故障，本次保留禁用缓存的策略。上述结果只说明本机源码、离屏、空列表场景的收益；发布 EXE、实际脚本配置、显卡渲染和冷启动需要另测，不能据此承诺同等加速。

首次带 `-X importtime` 的采样曾测得总导入 2.35 秒，其中 requests 约 0.96 秒；它只用于寻找依赖热点，不与后续普通启动结果混作加速比例。
